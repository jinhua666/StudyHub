# StudyHub 学习文档

围绕用户指定的主题、基础和学习目标，制作准确、易读、可复习的中文 Markdown 学习资料，并优先导入用户当前使用的 StudyHub 知识库。保留用户明确提出的范围和深度；不要为了填充而堆砌章节。

## 编写与验证

1. 对不确定、变化较快或需要精确引用的技术内容检索可靠资料，优先原论文、官方文档和项目维护者资料；在文末附可访问的来源链接。明确区分事实、简化模型与推断，检查公式符号、维度和代码示例。
2. 根据主题组织概念、直觉、核心原理、公式或流程、必要的代码示例及复习要点。示例应可理解，避免无意义的篇幅。使用 UTF-8 Markdown；表格、列表和代码块保持规范。
3. 行内公式用 `$...$`，独立公式用独占行的 `$$` 分隔；使用标准 KaTeX 支持的 LaTeX，避免将公式放进代码块。最终检查渲染结果，尤其是下标、矩阵、反斜杠和括号。代码使用带语言标识的围栏，保留可复制的原文。
4. 有助于理解时配图，优先权威原论文、官方文档提供的架构图或流程图；例如 Transformer 总体架构。图须与内容相关、可读、能实际显示，并在图注附近标明来源和链接；遵守来源的使用条件。不要臆造图片链接或声称未验证的图片已验证。若合适图片不可用，可制作清晰的原创示意图，并注明是示意图；无法验证显示时明确说明。

## 只保留一份并导入

- 将 StudyHub 中 `notes.content_md` 作为正文的唯一持久副本，不在项目目录额外保留同一篇 Markdown 文件。创建时可在内存或临时位置准备内容；验证导入成功后只清理由本次任务创建的临时文件，不删除用户原文件。用户明确要求另存 `.md` 或导出时尊重其要求，并说明会有额外副本。
- 图片优先使用可公开访问且允许引用的稳定 HTTPS 图片链接，以避免在本机再存一份；明确告知外链依赖网络。若用户要求离线使用，或外链不可靠而确有必要，上传图片到该篇笔记的 StudyHub 附件接口，正文用 `![说明](/api/attachments/附件ID)` 引用；每张图片只上传一次并重复引用同一 ID，不保留第二份本地图片。不要声称 StudyHub 当前的分类/全库导出一定能将该 API 链接转换为可离线使用的相对路径。
- 使用当前运行中的桌面程序所连接的本地 API，不要假定固定 8000 端口，也不要直接猜测数据库路径：桌面版使用随机本地端口，Windows 环境可能存在不同数据目录。可检查 StudyHub 进程的本地监听端口，逐个验证 `/api/categories` 和 `/api/notes`；存在多个实例或目标不明确时，先确认用户当前使用的是哪一个。禁止扫描非本机地址。程序未运行时，先确定用户实际知识库位置，不能确定时请用户打开 StudyHub，而不是静默创建另一份空库。
- 写入前通过 `/api/categories` 获取动态分类树，用返回的完整路径和 ID 匹配最合适的分类。分类不存在时，遵循用户意图，通过 API 在合适的现有板块内创建必要的子分类；不要硬编码分类 ID。先检索同名文档并核对分类；默认不覆盖或重复导入已有文档。只有用户明确要求更新特定文档时，读取原文并使用其 ID 更新，保留无关字段。
- `POST /api/notes` 接受 `title`、`summary`、`content_md`、`category_id`、`tags`、`status`、`difficulty`、`is_favorite`、`source_url`；用户未要求状态和难度时使用默认值。也可用 `/api/import` 接收包含 Front Matter 的文本，但导入无 ID 的文件会创建新文档。上传附件使用 `POST /api/notes/{id}/attachments`，响应 ID 用于正文图片链接。
- 写入后通过同一实例的 API 重新读取文档，核对标题、路径、正文、公式及图片链接；如可操作软件，再检查阅读页面图片和公式是否显示。附件上传后再更新正文，避免留下无效链接；失败时说明未完成步骤，不报告成功。最终告知文档标题、分类、导入结果、图片来源及是否依赖网络；不声称已生成独立 `.md` 文件，除非确实保留了它。

项目移动或换电脑后，不要使用旧电脑的绝对路径。接口说明可从当前运行的 StudyHub 进程对应的项目目录寻找 `docs/API.md` 和 `docs/AGENT_IMPORT_FORMAT.md`；若只有已打包程序，则直接查阅当前实例的 `/openapi.json`。优先使用当前窗口的 API 确认目标知识库，不依赖 Markdown 临时文件所在位置。
